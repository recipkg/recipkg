# 为项目定制 README

README 是给特定用户群的入口，不是统一生成的模板。先理解软件，再写内容。

## 研究和写作步骤

1. 读源码入口、包管理清单、CLI/API、现有 docs、示例、测试和真实可运行命令。只描述已实现的功能。
2. 找 2–4 个同类型、维护良好的项目作为表达参考：CLI 对照 CLI、库对照库、桌面应用对照桌面应用。记录它们如何组织安装、首个成功示例、兼容性和进阶文档；不要复制句子、图片、品牌或未经验证的承诺。
3. 确认 README 的语言、目标读者、最重要的一件事、可复现 demo、安装渠道、平台限制和联系/支持入口。缺少的信息用短问题一次询问；不能从源码确认的部分标成未知。
4. 先写最短的价值说明和能成功运行的 quick start。后续章节只在对用户有帮助时加入；避免为了徽章或目录增加空标题。
5. 检查每条命令能在干净环境运行、链接真实存在、版本范围准确、命令输出与代码一致；代码块不是测试过就标成示例，不声称已验证。

## 可按项目类型组合的章节

| 项目类型 | 常见的读者问题 | 可选章节 |
| --- | --- | --- |
| CLI 工具 | 怎么安装、常用命令、输入/输出是什么 | 一句话用途、安装、3 个常见命令、选项、配置/退出码、卸载 |
| 语言库 | 如何安装、调用什么 API、支持哪些 runtime | 安装、最小代码示例、API 链接、兼容矩阵、迁移说明、开发/测试 |
| Web 前端 | 用户看到什么、如何本地运行、生产怎么部署 | 产品截图/演示、环境变量、开发命令、构建、部署、浏览器兼容 |
| 服务/后端 | 如何配置、端口和健康检查、如何运维 | 架构图（如有帮助）、配置表、启动/健康检查、数据/升级/备份、API 文档 |
| 桌面/移动应用 | 支持哪些系统、去哪下载、如何升级 | 截图、系统要求、签名下载、权限说明、升级/卸载、已知问题 |
| 插件/扩展 | 如何安装、兼容哪个宿主、权限为何 | 宿主版本、安装步骤、权限说明、示例、更新/卸载 |
| 基础设施/容器 | 怎么部署、需要哪些权限/资源、如何回滚 | 部署前提、最小示例、配置、权限边界、升级/回滚、清理资源 |

## README 与包布局

根 README 负责帮助人判断和开始使用；API 参考、完整教程、设计说明放 `docs/`，不用把所有内容挤进 README。发行包的安装说明要与实际 registry、Release 和包清单吻合。若项目是 monorepo，在根 README 解释工作区关系，并为每个可独立发布 package 提供自己的 README。

适当时加入 LICENSE、CONTRIBUTING、SECURITY、CHANGELOG、Code of Conduct；许可证具有法律影响，不替用户选择或修改。徽章必须有真实目标和可维护来源。项目若暂无测试、版本、平台或安全承诺，不添加虚构徽章或宽泛保证。

参考 GitHub 的 [README 用途与展示规则](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)。
