# 发现依赖

## 输入

软件配方、已有依赖和可选的目标能力或来源范围。

## 步骤

1. 使用 `recipkg discover <package>` 生成标准分析提示词。
2. 从行为和接口推导必要能力，检查已有递归依赖是否覆盖。
3. 区分可直接复用的配方、需要提炼的源码仓库、参考资料和外部工具或服务。
4. 核实候选来源与版本，标记缺失节点、冲突和循环；推断不得写成已验证事实。
5. 输出最小必要依赖集合，以及后续添加或提炼工作。

## 输出与验收

交付包含别名、用途、来源、版本、证据及状态的建议表。发现候选不代表已安装依赖，也不代表依赖已通过验证。
