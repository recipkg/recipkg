# 重写某个软件

## 输入

现有配方、明确的新需求，以及可选的旧实现供观察。

## 步骤

1. 使用 `recipkg rewrite <package> --request "本轮要求"` 生成标准提示词。
2. 先更新需求、接口、依赖和验收条件，标明应保留与应改变的公开行为。
3. 保留旧产物，在单独目录依照新配方生成实现；避免依赖未写入配方的旧源码细节。
4. 执行验收并比较新旧行为，记录预期变化和意外差异。
5. 更新配方版本，重新打包并检查归档，以更新锁定信息并验证结构。

## 输出与验收

交付新配方、新实现和行为变更记录。只有实际验证的行为才能标为通过；命令输出提示词不代表重写已完成。

## 配方与生成源码布局

以配方、规范和验收合同作为主要输入；生成实现默认位于 `generated/`（generated 表示已生成的结果），不额外套层；需要独立源码版本管理时，直接将该目录作为固定提交子模块。项目保持原名，源码仓库名称全小写、连字符。不要将实现源码打进配方归档，也不要为迁就实现削弱验收。保留原有未提交工作；发布 GitHub 配方仓库时添加 `recipkg` topic 并核对。
