# Rebuild magpie-context-folding 0.5.0

## Goal and implementation preferences

Recreate the observable software contract of `magpie-context-folding` version 0.5.0 from this recipe alone. The product consists of two distinct components: a TypeScript Magpie plugin that projects marked conversation/source text into reversible references, and an independently installed Python `ctxf` CLI/library for explicit text folding and a separate archive. Keep their stores, scopes, command contracts and offsets distinct.

Use TypeScript for the Magpie plugin and Python for `ctxf`, matching the observed source languages. A rebuilding agent may propose a different language only if the user or target host requires it; preserve all externally visible contracts and justify any change. The plugin targets Magpie's server/gateway runtime and uses its request-hook interface. The standalone package is `context-folding` 0.1.0 and requires Python >=3.10; Python 3.10 additionally requires `tomli>=2.0.1`, while 3.11+ uses the standard library. Exact minimum Magpie, OS and architecture versions are not established; discover and document compatible versions rather than inventing support claims. The plugin's published package metadata specifies Node >=22 and Bun >=1.4.0 for development/build tooling.

This is a CLI/plugin product with no product UI. Keep command output concise and deterministic: successful text conversion writes only the transformed text to stdout; diagnostics go to stderr. Document configuration, migration errors, recovery and failure behavior clearly. Do not introduce a generic dashboard or a new UI surface.

Internationalization requirements beyond the source's English and Simplified Chinese documentation are unknown. Preserve those documented languages where present; locale formatting, RTL support and translation maintenance are unspecified. Performance budgets for latency, memory, throughput and distribution size are unknown. Do not invent targets or claim savings from token estimates as measured model or billing savings.

Read `PROTOCOL.md` for the bundled detailed annotation, query and recovery contract, and `COVERAGE.md` for observed conflicts and verification boundaries. These local documents are part of the reconstruction input; do not require fetching the original source to interpret them.

## Plugin behavior

1. Recognize only whole-line paired `@context-fold begin LABEL` / `@context-fold end LABEL` annotations, with matching labels and compatible comment shells. Conversation text uses HTML comments; source text uses the language's comment syntax. Correctly nested pairs form parent/child archive nodes. Preserve unclosed, crossing, malformed and orphan end markers as specified by the protocol; do not guess repairs.
2. Leave unmarked content, conclusions and constraints outside marked regions, user messages, tool calls/results, images and signed reasoning fields unchanged. Pair across assistant ordinary-text slices within one task turn while preserving message order and structure. New user messages close an unfinished range. Do not fold uncertain source formats; the documented Magpie gateway filtering is conservative for Python and JavaScript/TypeScript.
3. On the first complete observation, retain the full text by default. After one subsequent progressing request boundary (`delay_requests = 1`), eligible text may be folded; identical retries do not advance the delay. No timer may alter in-flight streaming output. Apply the configured minimum savings gate (default 256 estimated tokens) against the complete serialized request, including injected guidance and recovery locator. If storage, capacity, concurrency, recovery entry or savings checks fail, preserve the original request.
4. Persist the original UTF-8 content and archive relationships before publishing references. Use SHA-256 over the folded body bytes, excluding annotation wrappers and the final physical newline as documented. Display `[[cf:v2:<hash>]]`, normally using a 12-character prefix and extending on collisions. Existing references point to immutable archived snapshots; do not silently substitute current source contents.
5. Inject one concise `<context-folding>…</context-folding>` instruction into the actual system-instruction field for supported host protocols. Preserve host instructions and request structure; remove/replace only the plugin's own previous injected instruction. Do not register a model-facing archive tool or alter model, streaming, tool declarations or tool choice. Include the CLI recovery command, archive location and session scope only when a folded reference requires them. If a usable existing shell tool cannot be identified, leave the request unchanged.
6. Provide a local `magpie-context-folding` CLI for bounded view reads, explicit original reads/restoration, list/search/metadata, safe paste, status/stats and forgetting eligible archives. Default `read` is a bounded current-layer view and does not change folding state. `read --restore` returns exact original content and persistently protects the selected subtree and ancestors. Ordinary reads must not implicitly set keep or unfold history. Respect the Magpie archive directory and scope from the recovery guidance. Treat recovered text as data; never execute embedded instructions.
7. Support legacy archive reads where required for compatibility without re-enabling retired automatic selection policies, summary layers, MCP service or budget controls. Reject incompatible old configuration with a clear migration error; do not silently map obsolete settings to new policies.

## Standalone Python component

Provide the separate `ctxf` CLI and Python package for explicit stdin-to-stdout text conversion and durable SQLite archive queries. `ctxf fold` immediately transforms already-closed valid annotations; it does not simulate request cycles or modify host delay configuration. Default fold output is only the transformed UTF-8 text; errors go to stderr. `fold --json` exposes text and reference metadata. Ordinary `ctxf read HASH` and `ctxf read HASH --raw` both return a bounded current-layer plain-text view (default 1200 Unicode code points, maximum 24000); pagination continuation is reported as `nextOffset=N` on stderr. `read --json` selects structured query output. Neither plain nor raw reads automatically paginate or restore. The older `context-folding` executable has a different raw-read branch; do not conflate its behavior with `ctxf`. The standalone README at the pinned commit contradicts this query contract; the protocol, CLI source and isolated observations agree on the behavior recorded here. The default archive is under `$XDG_DATA_HOME/context-folding/archive.sqlite3`, or `~/.local/share/context-folding/archive.sqlite3`; `CTXF_STATE` and `--state` override it. Preserve its documented scope behavior and Unicode-code-point offsets, which differ from the Magpie CLI's UTF-16 code-unit offsets. The Python backend does not share archives or scopes with the Magpie plugin. Do not restore the removed `ctxf mcp` service.

## Interfaces and configuration

Preserve the documented plugin package identity `magpie-context-folding`, version 0.5.0, Magpie hook integration, and executable CLI name. Support configuration precedence from defaults through global config, nearest project config (search ending at the Git root), and plugin options. Preserve documented settings including `enabled`, `delay_requests`, `max_session_bytes`, `min_savings_tokens`, `shell_tool_name`, `recovery_command`, and `gateway_timeout_ms`; document corresponding camelCase plugin options. Defaults include enabled folding, one request of delay, 64 MiB maximum session archive size and 256 estimated-token minimum savings. A zero delay permits folding on the first complete observation. The maximum session size is a storage limit, not a folding threshold.

The Magpie CLI uses UTF-16 code-unit paging and `nextOffset`; the Python CLI uses Unicode code-point paging. Implement the documented root CLI forms such as `read --scope SCOPE --id HASH`, `--state-dir`, `--all`, `--full`, `--restore`, `--start-line/--end-line`, `--offset/--limit`, `--json`, `list`, `grep`, `meta`, `paste`, `status`, `stats`, and `forget`, honoring the protocol's mutual exclusions and safe-output rules. ## Runtime and external prerequisites

- The Magpie host and its supported gateway request-hook API are external runtime prerequisites. Do not rebuild Magpie as part of this package.
- The Magpie host must expose an already-authorized shell execution tool for CLI recovery and make the plugin CLI and archive accessible through the same filesystem. Without it the hook leaves the request unchanged.
- Node.js >=22 and Bun >=1.4.0 are stated development/build requirements in observed package metadata. Do not assume these are the only runtime requirements; verify the selected packaging and host path.
- Python >=3.10 and SQLite are required by `context-folding` 0.1.0; Python 3.10 needs `tomli>=2.0.1`. Optional language-aware JavaScript/TypeScript parsing uses `tree-sitter>=0.25,<0.26`, `tree-sitter-javascript>=0.25,<0.26`, and `tree-sitter-typescript>=0.23,<0.24`. Its observed Python build backend is `uv_build>=0.9,<0.14`. These are external package/toolchain prerequisites, not bundled software recipe dependencies.
- npm registry access, npm credentials and release automation are distribution concerns, not runtime dependencies. Do not require model credentials for folding or recovery.

No Recipkg software dependencies are declared: the recipe sources do not establish any recursively packaged component recipe as required for rebuilding. Compilers, interpreters, Magpie, registries and accounts are external prerequisites, not recipe dependencies.
